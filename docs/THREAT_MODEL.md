# Threat model

## System boundary

```text
WebGPT planner
  -> authenticated MCP connector/tunnel
KAI Work Host instance
  -> pinned DSH SDK runtime and isolated DSH home
Luna worker
  -> one explicitly registered local project
```

KAI Work Host is the execution-management and memory layer. DSH remains the
only AgentLoop, named Session, event, tool, sandbox, and model-adapter
substrate. A deployment instance owns one state root, one DSH home, and one
connector identity. Two computers or regions must not share these writable
roots, OAuth grants, runtime keys, tunnel profiles, or active tunnel IDs.

## Trusted inputs

- The operator-selected exact project root and its maximum allowed permission
  profiles.
- The checked source release and its SHA-256/manifest.
- The DSH version and commit in `config/dsh-pin.json`.
- The machine-local deployment configuration generated by the installer.

Chat messages, prompts, attachments, repository files, tool output, and model
responses are untrusted data. They do not authorize a wider project,
permission, network, publishing, messaging, deployment, or secret disclosure.

## Protected assets

- OAuth grants and provider credentials.
- Tunnel runtime keys and tunnel identifiers.
- Project source and formal truth.
- Durable Task/Session state, receipts, L0/L1/L2 memory, logs, and attachments.
- The operator's machine outside the registered project root.

## Enforced controls

- Loopback bind by default; bearer token required for non-loopback HTTP.
- Exact project canonicalization and per-project permission ceilings.
- Durable WebGPT conversation, Task, request-id, and terminal-job ownership.
- One writer lease per state root.
- Path containment checks that reject symlink/junction escape.
- DSH identity verification by package version and Git commit.
- Separate DSH home and OAuth grant for each Host instance.
- At-most-once model turns after uncertain process failure.
- No provider/API-key fallback and no account rotation on usage-limit errors.
- Release allowlist, secret scan, SBOM, file manifest, and SHA-256 checksum.

## Important limitations

- `network_access=false` is a model/task policy. It is not an OS firewall.
- DSH file sandboxing is a defense layer, not a substitute for Windows account,
  ACL, endpoint-security, backup, or virtual-machine isolation.
- A `danger-full-access` project authorization intentionally permits broad file
  access and must be granted only by the machine owner.
- Direct terminal and file tools can modify an authorized workspace without a
  second local planner; this is the intended WebGPT-as-brain design.
- The Host does not emulate browser/computer-use, deployment, publishing,
  messaging, or Git push. Those require a separate native path and authority.
- Provider, ChatGPT, Codex, connector, tunnel, and model availability can
  change independently. Compatibility is not an endorsement or service-level
  guarantee.

## Failure policy

Identity mismatch, missing build output, missing grant, workspace mismatch,
permission expansion, cross-conversation access, ambiguous process ownership,
and provider-limit errors fail closed. Recovery reads durable state and asks
the WebGPT planner to inspect current project evidence before a new turn; it
does not automatically replay an uncertain mutation.
